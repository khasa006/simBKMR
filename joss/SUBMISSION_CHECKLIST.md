# JOSS preparation checklist

This is a non-invasive planning checklist, **not** a declaration of submission readiness.

- [ ] Decide whether the software submitted is the CRAN package `simBKMRdata` or a separately maintainable `simBKMR` software workflow.
- [ ] Confirm JOSS authors, consent, order, ORCID identifiers, affiliations, and software contributions. The draft paper includes a provisional author only.
- [ ] Verify complete citation data for the two methods studies and clarify their connection to exact package functions or precursor scripts.
- [ ] Review research impact evidence and public development history under current JOSS pre-review rules.
- [ ] Verify example dataset permissions and third-party materials.
- [ ] Run software tests and document installation from a clean R environment; check numerical validation of Gamma simulation and threshold behavior.
- [ ] Render and proofread `paper.md`, resolve citations, update AI-use disclosure, and verify JOSS word count.
- [ ] If the package is submitted, request explicit permission before placing paper files on a temporary `simBKMRdata` branch, which may remain unmerged.
- [ ] If the analysis project is submitted instead, document how users run and test the reusable software without historical private file paths.
- [ ] Submit to JOSS only after all authors have reviewed and the software meets repository and screening requirements.

Original analyses and release records are not to be removed, renamed, or silently edited.
